# ADR-5: возвраты в платёжный шлюз не повторяются автоматически

Статус: принято, 10 сентября 2026.

## Контекст

INC-58 (3 сентября 2026): шлюз отвечал медленно, наш клиент получал таймаут, а возврат на
стороне шлюза к этому времени уже проходил. Повторный запрос создавал второй возврат: 23
покупателя получили деньги дважды, 41 800 ₽ вернуть не удалось. В API v2 шлюза у запроса на
возврат нет ключа идемпотентности: каждый запрос — новый возврат.

## Решение

- `refund()` не повторяется автоматически — ни в коде, ни фоновой задачей — до перехода на API v3
  с ключами идемпотентности (план: I квартал 2027).
- При таймауте возврат получает статус `pending` и закрывается вебхуком шлюза
  (`refund.succeeded` / `refund.failed`) или утренней сверкой в 06:00.
- Повторить возврат вручную оператор может только после того, как сверка показала, что возврата
  в шлюзе нет.
